Nexa 功能架构图

依据 docs/product-design.md（v0.1）梳理：先给出整体功能架构（三端接入 → 中继通道 → 本地核心），再逐个拆解九个大模块的功能层级。图中节点的编号与文档章节一一对应。

FIGURE 01 · OVERALL

整体功能架构

左→右三层：三端入口汇聚到腾讯云中继，中继把手机端与插件端的请求转发给桌面端本地核心；本地核心以「对话式任务」为主入口，向下调度 Agent 三层能力并沉淀数据。

MODULE 01 · §3.1 CORE TASK

对话式任务

用户最主要的入口：先用自然语言描述需求，Agent 自主识别意图、拆解 Plan、按需激活能力，产物落到会话工作区；定时任务不设独立新建入口，全部收敛在对话里创建。

MODULE 02 · §3.2 AGENT LAYERS

Agent 三层能力模型

Nexa 的核心设计：专家决定「以什么角色、带哪些工具跑」，Skill 决定「这一步能调用什么能力」，连接器决定「能触达哪些外部系统」。三者的目录与 YAML 描述对齐 WorkBuddy，便于互相导入。

MODULE 03 · §3.3 SKILL PACKS

技能包管理

左侧菜单入口，统一管理系统内置与用户自建的三类对象：Skills、专家、连接器。三者都支持列表查看与编辑，差别在于各自可配置的字段。

MODULE 04 · §3.4 LIBRARY

资料库

两个子系统共用一个页面：文件 tab 存放文章 / 图片 / 文档 / 任务产物，笔记 tab 存放结构化 markdown 笔记（草稿与已提交两态）。笔记既能手写，也能由对话里「记一下…」自动创建与追加。

MODULE 05 · §3.5 SCHEDULER

定时任务

这个菜单只展示与管理，不提供新建入口——新建全部收敛在对话里。每条任务要能看清「什么时候跑、上次跑得怎么样」，并支持暂停、改规则、立即执行、删除。

MODULE 06 · §5 RETRIEVAL

知识库召回（不用 RAG）

不做 embedding + 向量库：用 SQLite 元数据索引做粗筛，把候选的摘要与关键词交给 LLM 重排，最后把 Top-3 的完整文件塞进上下文窗口。个人数据量级下精度够、零维护。

MODULE 07 · §5.4 / §6 MEMORY

自进化记忆层

与「单文件追加」的本质区别：记忆是结构化 SQLite 行，分三层存储、自动提取、旧条目 superseded 软淘汰。长期使用后条目数稳定，注入 prompt 的体积可控。

MODULE 08 · §3.6 / §3.7 / §2

三端协同（手机端 / 浏览器插件 / 中继）

桌面端是主入口，手机端与插件端通过腾讯云中继接入：手机端负责通勤时发起任务与远程续跑，插件端负责把浏览器里的页面与图片一键送进资料库。

MODULE 09 · §7 / §4.1 SETTINGS

系统设置与初始化引导

首次启动走四步向导（用户名 → 默认模型 → 偏好 → 手机配对），完成或跳过后写入本地配置；之后的日常调整都在设置弹框里按分类进行。

读图方式

每个模块图为三层：根节点 = 功能模块，第二层 = 功能组，组内每一行 = 功能点。组内用包含关系表达层级，不再画连线，避免 5×5 的连线噪声。

与文档的对应

整体图节点名取文档 §3 的模块名；模块图的 eyebrow 标注对应章节号（如 3.4 / §5 / §7），可回到 product-design.md 逐条核对。

取舍说明

v2 规划（iOS / 鸿蒙、多人协作、订阅、云同步）不进图；整体图把「知识库召回」与「自进化记忆层」合并为一个数据节点，两者在模块图中各自展开。
