# Nexa · 产品方案 v0.1

> 目标：在正式编码前，将 Nexa 的产品定位、功能模块、交互设计、知识库与记忆策略、三端协同方式形成可评审的完整方案。

---

## 1. 定位与愿景

**一句话定位**：Nexa 是个人用户的智能工作伙伴——懂我、帮我、陪我成长。

它区别于纯「对话机器人」和纯「自动化流程」，提供三种价值：

| 价值 | 含义 | 典型场景 |
|------|------|---------|
| **帮我干活** | 一句话指派，Agent 自主规划与执行，交付可验证的结果文件 | 生成周报、数据分析、旅行规划、写代码做小应用 |
| **整理碎片** | 对话中自然收集到的 URL、图片、笔记，自动沉淀为结构化知识库 | 浏览器插件采集文章 → 对话中收藏图片 → 自动打标签归档 |
| **陪我成长** | 对话过程中持续学习用户偏好、工作方式、关注方向，越用越懂你 | 自动识别你偏好的报告格式、记住你关注的股票池、在合适时机主动提醒 |

### 1.1 与同类产品的差异

- 对比 WorkBuddy：Nexa 额外提供**手机端远程操控**和**浏览器插件采集**，以及内建的**自进化记忆层**；Agent 架构上显式区分 Skills / 专家 / 连接器 三层。
- 对比 Dify/Coze：Nexa 是**个人本地优先**的桌面应用，不是平台；工作目录落在本地 `~/.nexa/workspaces/`，不做多人协作。
- 对比 Raycast：Nexa 是 **Agent-first**（对话驱动），不是启动器；强调长任务执行和产物沉淀。

### 1.2 目标用户画像

- 知识工作者（产品、运营、研究、独立开发者）
- 日常有大量碎片化信息收集与整理需求
- 愿意接受 Agent 自主执行、追求"一句话出活"的效率增益
- 可能同时有桌面和 Android 设备，希望手机能远程续跑任务

## 3. 功能模块详述

### 3.1 对话式任务（核心）

这是用户最主要的入口。桌面端默认展示「新任务」对话页，用户直接用自然语言描述需求。

**对话过程中 Agent 的行为**：

1. **意图识别**：判断任务类型（笔记/收藏/分析/代码/定时/…）
2. **自主拆解**：复杂任务拆成多步骤 Plan，展示在对话流中
3. **能力调用**：按需激活 Skills、切换专家、调用连接器（后续 3.2 详述）
4. **文件产物**：所有产物写入 `~/.nexa/workspaces/<session-id>/` 并在右侧面板可见
5. **记忆提取**：每轮结束后，判断是否需要更新用户记忆（偏好、状态、关注）

**支持的任务类型（首批）**：

| 类别 | 示例 |
|------|------|
| 笔记 | "记一下今天产品周会的三个关键结论" |
| 收藏文章 | "把这个 URL 收一下"（或浏览器插件已采集的链接直接进入对话） |
| 收藏图片 | 直接在对话中粘贴图片 |
| 数据分析 | "分析这个 CSV，给出要点和图表" |
| 股价分析 | "帮我看看特斯拉最近走势" |
| 旅行规划 | "下周末去杭州帮我规划两天行程" |
| 写代码 | "帮我写一个 Python 脚本批量重命名图片" |
| 做应用 | "帮我做一个本地记账小应用，HTML 单文件就行" |
| 定时任务 | 对话中说出"每天早上 9 点帮我看一眼特斯拉行情" → Agent 自动创建 cron 任务，**不暴露新建入口** |
| 信息检索 | "帮我调研一下 Next.js 15 新特性" |

**定时任务的特殊处理**：用户只在对话中提需求，Agent 判断是否需要自动化 → 生成 cron job 写入本地调度器 → 出现在"定时任务"菜单里供后续管理。

### 3.2 Agent 三层能力模型（Skills / 专家 / 连接器）

这是 Nexa 的核心设计，直接影响技术架构。

```
┌─────────────────────────────────────────┐
│           用户对话输入                     │
└──────────────────┬──────────────────────┘
                   ▼
        ┌────────────────────┐
        │   Agent Loop       │  ← @earendil-works/pi-agent-core
        │  (planner → act →  │
        │   observe → loop)  │
        └───┬───────┬────────┘
            │       │
     ┌──────┘       └──────────────────────┐
     ▼                                     ▼
┌───────────────┐                ┌─────────────────────┐
│   专家 Layer   │                │  Skills + 连接器     │
│               │                │                     │
│  角色提示词包   │                │  Skills:            │
│  + Agent Loop  │                │   · 能力模块(如 PDF   │
│    调度策略    │                │      解析、XLSX 生成) │
│  + 工具集子集  │                │   · 可被 agent 按需   │
│               │                │      加载调用         │
│  示例专家:     │                │                     │
│  - 研究员      │                │  连接器:             │
│  - 代码助手    │                │   · 外部系统接入     │
│  - 旅行顾问    │                │   · 如飞书、Notion、  │
│  - 数据分析员  │                │      行情 API、数据库 │
└───────────────┘                └─────────────────────┘
```

**三者定义与边界**：

| 概念 | 本质 | 生命周期 | 触发方式 |
|------|------|---------|---------|
| **专家 Expert** | 角色提示词包 + agent loop 调度策略 + 限定工具集 | 贯穿整个会话 | 用户对话前可预选；或 Agent 自动判断切换 |
| **Skill** | 一组可独立调用的能力模块（提示词 + 工具函数） | 单次任务内 | Agent 在 plan 阶段按需加载 |
| **连接器 Connector** | 外部系统的认证 + API 封装 | 长期存在 | Agent 调用时带上凭据 |

**与 workbuddy 的对齐**：Skills 和 Connector 的概念、目录结构、YAML 描述文件格式与 workbuddy 保持一致，便于后续互相导入。

### 3.3 技能包（左侧菜单入口）

管理系统内置和用户自建的三类对象：

- **Skills 管理**：列表视图、导入导出、启用/禁用、编辑 YAML 描述
- **专家管理**：角色描述、系统提示词、调度策略、可调用工具集的可视化配置
- **连接器管理**：连接状态、凭据存储位置、连接测试、最近调用记录

### 3.4 资料库（左侧菜单入口）

存放文件条目 + **结构化笔记** 两大子系统：

#### 3.4.1 文件子系统（笔记之外的条目）

| 条目 | 来源 | 存储形态 |
|------|------|---------|
| 文章 | 浏览器插件采集 / 对话中 URL | HTML → 可读文章（正文提取） |
| 图片 | 对话粘贴 / 浏览器插件 | 原图 + 描述 |
| 文档 | 上传 / Agent 生成 | docx / pdf / xlsx / pptx |
| 任务产物 | Agent 执行过程 | 目录下所有文件（按 session 分组） |

#### 3.4.2 笔记子系统（结构化，v1 新增）

**典型场景**：开会时记录多个问题 → 得到答案后逐条补充 → 形成完整会议笔记 → 提交保存并分类。

**笔记数据模型**：

```
Note {
  id, title, content(markdown),
  status: draft | submitted,
  category: 自定义分类（如"会议"/"学习"/"灵感"）,
  tags: ["技术分享","Q&A"],
  linked_session_id: 可选（关联某次 Agent 会话）,
  created_at, updated_at
}
```

**资料库页面布局（文件 tab + 笔记 tab 顶部切换）**：

```
┌─ 资料库 ──────────────────────────────────────────────────────┐
│ [🔍 搜索...]                                                  │
│ [📂 文件]  [📝 笔记]  ← 顶部 tab 切换                         │
├─ 笔记 tab ───────────────────────────────────────────────────┤
│ ┌─ 左侧分类 ──┐  ┌─ 中间笔记列表 ──────────────────────────┐ │
│ │ + 新增笔记   │  │ ▾ 📁 会议 (3)                          │ │
│ │              │  │   · 技术分享会 Q&A  [草稿]  [未分类]   │ │
│ │ 📁 会议    3 │  │   · 产品周会要点     昨天              │ │
│ │ 📁 学习    2 │  │   · 评审会议纪要    3 天前             │ │
│ │ 📁 灵感    4 │  │ ▾ 📁 学习 (2)                          │ │
│ │ 📁 未分类  1 │  │   · LangGraph 论文精读 3 天前           │ │
│ └──────────────┘  └────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

**笔记编辑器视图**（点中间列表的一条笔记进入全页编辑）：

```
┌─ 编辑中：技术分享会 Q&A ────────────────────────────────────┐
│ 分类: [会议 ▾]  标签: [#技术分享 #Q&A]  状态: 🟡 草稿        │
│                                                              │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ ## 技术分享会 Q&A                                        │ │
│ │                                                          │ │
│ │ ### Q1: Agent 的沙箱隔离怎么实现？                        │ │
│ │ **A1:** 用 Docker 容器 + 只读根文件系统，每个 session ... │ │
│ │                                                          │ │
│ │ ### Q2: 知识库召回为什么不用 RAG？                        │ │
│ │ **A2:** SQLite 粗筛 + LLM 重排，对个人量级足够且零维护 ... │ │
│ │                                                          │ │
│ │ ### Q3: (待补充)                                         │ │
│ │                                                          │ │
│ │ _+ 点此继续编辑..._                                      │ │
│ └──────────────────────────────────────────────────────────┘ │
│                                                              │
│ 关联会话: [选择 ▾]  或 留空                                   │
│                                                              │
│ [💾 保存草稿]  [✅ 提交保存并分类]  [🗑️ 删除]  [← 返回列表]   │
└──────────────────────────────────────────────────────────────┘
```

**关键交互**：

| 动作 | 流程 |
|------|------|
| 新增笔记 | 资料库「＋ 新增笔记」→ 进空白编辑器；或在对话里说"记一下 xxx"→ **Agent 自动创建草稿笔记**（category 默认「未分类」） |
| 继续编辑草稿 | 列表中草稿状态标签 → 进编辑器继续写 |
| 保存草稿 | 编辑过程中自动定时保存（每 30s），也可手动存 |
| 提交保存 | 点「✅ 提交」→ 状态变 submitted → **不强制选分类**（允许提交到「未分类」，用户之后再整理） |
| 补充 Q&A | v1 通过 markdown 自由编辑；对话里追加 Q3 → **Agent 自动向草稿笔记追加 markdown 块**（Note:append IPC） |
| 分类管理 | 左侧「+ 新增分类」，支持自定义；内置 4 个预设：会议/学习/工作/灵感 |
| 笔记被 Agent 自动生成 | 对话中"记一下…"→ Agent 调 note.create，status=draft，category=未分类 → 用户之后去资料库补全提交 |

**设计原则**：
- 笔记是**结构化的 markdown 文档**，不是 chat 气泡的堆砌
- 草稿和已提交分开筛选，用户在开会时可以快速写一堆问题不着急分类，会后补答案 → 一次性提交
- 分类是扁平字符串（v1 不做多级分类），简单够用

**资料库页面整体交互**：
- 顶部 tab：📂 文件 | 📝 笔记
- 文件 tab：左侧类型+标签筛选 + 中间卡片流 + 右侧预览面板（现有逻辑）
- 笔记 tab：左侧分类目录 + 中间按分类分组的笔记列表 + 新增按钮 + 点击进编辑器

### 3.5 定时任务（左侧菜单入口）

- **只展示与管理**，不提供新建入口（新建全部收敛在对话中）
- 每条任务展示：描述、触发规则（cron 表达式 + 自然语言解释）、下次执行时间、最近 5 次执行记录
- 操作：暂停 / 开启 / 编辑 cron 规则 / 查看执行产物 / 立即执行一次 / 删除

### 3.6 手机端

**核心使用场景**：
1. **通勤路上** → 发起一个"帮我调研 XXX"的任务，到公司时电脑已经跑完
2. **外出** → 收到 Agent 通知"任务已完成，有 3 个产物需要你确认"，在手机上快速查看并回复继续
3. **续跑** → 电脑上 Agent 做到一半需要你决策，手机端接收到请求，做选择后任务继续

**页面结构**：
- 首页：电脑状态（在线/离线）+ 最近任务卡片 + 继续执行中的任务入口
- 会话列表：与桌面端同步，可进入查看完整历史
- 资料库：轻量浏览，支持收藏和简单搜索
- 设置：配对管理、通知偏好

**与电脑的配对流程**：
1. 桌面端首次打开 → 设置页面显示"手机配对"入口 → 生成 6 位码 + 二维码
2. 手机端扫码或输入码 → 腾讯云中继建立双向 WebSocket 通道
3. 桌面端推送所有会话元数据 → 手机端渲染

### 3.7 浏览器插件端

三个核心功能：

| 功能 | 操作 | 落地 |
|------|------|------|
| 采集 URL 为文章 | 插件图标 → "采集此页面" | 发送到中继 → 桌面端 Agent 执行正文提取 + 存入资料库 |
| 收藏图片 | 右键图片 → "Nexa 收藏图片" | 直接上传到桌面端资料库（通过中继） |
| 快速搜索 | 插件图标 → 搜索框 | 在浏览器中搜索自己的 Nexa 资料库条目 |

## 4. 关键交互流程

### 4.1 首次启动 → 初始化

```
┌─────────────────────────────────────────┐
│  Nexa 欢迎页                              │
│                                          │
│  1. 设置用户名（Nexa 怎么称呼你？）         │
│  2. 选择默认模型（OpenAI / Anthropic）    │
│  3. 可选：收集偏好（职业、行业、关注方向）   │

```

完成后写入本地 `~/.nexa/config.json`。

### 4.2 新建任务流程（含模式选择）

新建任务时，先让用户选择**任务模式**：

```
┌──────────────────────────────────────────────────────────────┐
│  Nexa · 新建任务                                              │
│                                                              │
│  选择任务类型:                                                │
│                                                              │
│  ┌────────────────────┐  ┌────────────────────────────┐     │
│  │ 🎯 自由任务          │  │ 💻 项目编码                 │     │
│  │                     │  │                            │     │
│  │ 写报告、数据分析、   │  │ 在已有项目目录上改代码      │     │
│  │ 调研、做规划...     │  │                            │     │
│  │                     │  │ 选择目录 →                   │     │
│  │ 系统自动创建隔离工作区│  │ /Users/bondli/projects/... │     │
│  │ ~/.nexa/workspaces/ │  │                            │     │
│  └────────────────────┘  └────────────────────────────┘     │
│                                                              │
│  然后输入描述...                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ 帮我写一份关于 AI Agent 框架的调研报告...                │  │
│  └────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

两种模式的差异：

| 维度 | 自由任务（free） | 项目编码（project） |
|------|------------------|-------------------|
| workspace_path | `~/.nexa/workspaces/<uuid>/` 自动创建 | 用户选择的已有目录 |
| 顶部 bar | 显示"自由模式"标签 | 显示项目路径 + 项目名 |
| Agent 行为 | 产物直接写到自动创建的目录 | 知道自己在操作真实项目，更谨慎 |
| System Prompt | 标准角色 + 记忆 | 角色 + 记忆 + **项目目录扫描**（自动读 AGENTS.md / README.md） |
| 会话删除 | **清理 workspace 目录** | 只删会话元数据，**不动项目文件** |

### 4.3 执行与产物沉淀（free 模式示例）

```
用户输入: "帮我写一份关于 AI Agent 框架的调研报告"  [free 模式]
    │
    ▼
Agent 判断需要 "研究员" 专家 ──► 自动切换到该专家
    │
    ▼
Plan 生成:
  Step 1: 使用 deep-research Skill 检索 5 个来源
  Step 2: 整理为对比表
  Step 3: 输出 HTML 报告
    │
    ▼
逐步执行，每一步在对话流中展示进度 + 产物链接
    │
    ▼
执行完成
  ├─ 产物存入 ~/.nexa/workspaces/<session-id>/
  ├─ 自动同步到资料库（标记为"调研报告"）
  └─ 记忆提取: 用户关注方向 → 追加 AI Agent 框架
```

### 4.3 定时任务创建（对话驱动）

```
用户输入: "每天早上 9 点帮我看一眼特斯拉的股价，有异动告诉我"
    │
    ▼
Agent 识别: 意图 = 创建定时任务
    │
    ▼
自动生成:
  ├─ cron 表达式: 0 9 * * *
  ├─ 执行脚本: python3 ~/.nexa/jobs/tsla_monitor.py
  ├─ 通知方式: 桌面通知 + 手机推送（已配对时）
  └─ 注册到本地调度器
    │
    ▼
在对话中回复: "好的，已为你创建每天 9:00 的特斯拉股价监控任务"
    │
    ▼
任务出现在"定时任务"菜单
```

### 4.4 手机端续跑电脑任务

```
1. 电脑上 Agent 执行到需要用户决策的节点
   → 生成一个 "需要输入" 卡片
   → 通过中继推送到手机端
2. 用户在手机端打开通知 → 看到决策选项
3. 点击选项 → 中继回传 → 电脑端 Agent 继续执行
4. 完成后 → 手机端收到结果推送
```

## 5. 知识库召回方案（不使用 RAG）

用户明确要求"不使用 RAG"，这与典型 AI 知识库方案不同。以下给出的是**最佳替代方案**：

### 5.1 核心思路：结构化索引 + 语义关键词 + LLM 直接读取

不走 embedding + vector DB 路线，而是让知识库对 LLM 来说**可见且可直接阅读**：

```
┌──────────────────────────────────────────────┐
│           Nexa 知识库召回                      │
│                                              │
│  1. 元数据索引（SQLite）                       │
│     - 标题 / 标签 / 创建时间 / 来源 URL       │
│     - 自动摘要（由 Agent 在入库时生成）         │
│     - 关键词列表（LLM 提取，5-10 个）          │
│                                              │
│  2. 全文缓存（文件系统）                       │
│     - 笔记 → .md                              │
│     - 文章 → .html + 提取正文 .md             │
│     - 图片 → 原图 + OCR 文本 .txt              │
│     - 文档 → 转换后的 .md                     │
│                                              │
│  3. 召回路径（Agent 内建工具）                  │
│                                              │
│     ┌─────────────────────────────────┐      │
│     │ 用户问: "我之前收藏的那篇关于     │      │
│     │        LangChain 的文章"         │      │
│     └─────────────────┬───────────────┘      │
│                       ▼                      │
│     ┌─────────────────────────────────┐      │
│     │ 工具: kb_search(query, opts)     │      │
│     │  第一步: SQLite 按关键词/标签/    │      │
│     │         时间粗筛 Top-N            │      │
│     │  第二步: 把候选条目的摘要+关键词  │      │
│     │         列表交给 LLM 重排序       │      │
│     │  第三步: 返回 Top-3 的完整文件    │      │
│     └─────────────────┬───────────────┘      │
│                       ▼                      │
│     LLM 将完整文件内容放入 context window      │
└──────────────────────────────────────────────┘
```

### 5.2 为什么不做 RAG

- **v1 明确不考虑 RAG**（不引入 embedding 模型，不引入向量数据库）
- 个人用户的数据规模（千-万级条目）：SQLite 粗筛 + LLM 重排足够精准
- 避免 embedding 模型成本和向量数据库维护
- 召回质量可被 LLM 自身的"理解"能力补强
- 上下文窗口越来越大（128K+），直接读全文变得可行
- 长期看如果精度不够**只优化 LLM 重排的 prompt**，不换架构

### 5.3 入库时的处理流程（Agent 自动完成）

```
新条目入库
  │
  ▼
1. 去重检查（URL hash / 标题相似度）
  │
  ▼
2. Agent 调用 LLM 生成:
   - 一句话摘要
   - 5-10 个关键词
   - 建议标签（可多选）
   - 建议分类（笔记/文章/图片/文档）
  │
  ▼
3. 写入 SQLite 索引 + 文件系统
  │
  ▼
4. 检查是否需要触发记忆更新（如内容与用户关注方向高度相关）
```

### 5.4 自进化记忆层（v1 核心能力）

#### 与 WorkBuddy memory.md 的本质区别

WorkBuddy 用 **单文件追加**（`~/.workbuddy/memory.md`）：所有对话里沉淀的信息按时间顺序 append 到一个 markdown 文件里，Agent 在构建 system prompt 时把整个文件内容拼进去。这有三个问题：

| 问题 | 后果 |
|------|------|
| **无结构化** | Agent 需要自己从大段 markdown 里"理解"什么有用，随着使用时间变长 prompt 会越来越冗余 |
| **无去重无 superseded** | 用户"之前说开本田 ADV350，现在换了川崎 Ninja 400"——旧信息不会自动失效，Agent 可能同时提到两个车型 |
| **无分层** | 用户长期偏好（"不喜欢 PPT 要 HTML 报告"）、当前状态（"正在摩旅西藏"）、临时上下文（"这轮对话在做调研"）混在一起 |

**Nexa 的方案：结构化 SQLite 三层记忆 + 自动提取 + superseded 淘汰**

```
┌─ Layer 1: profile（静态画像）─────────────────────────┐
│  稳定不变或极少变化的事实                               │
│  · 职业: 产品经理                                      │
│  · 兴趣: AI Agent / 摩托车 / 旅行                      │
│  · 常驻: 杭州                                          │
│  提取策略: 低置信度不写入，只写入反复确认的事实          │
├─ Layer 2: state（当前状态）────────────────────────────┤
│  可变、有时间性的状态                                   │
│  · 当前项目: finance-tracker                           │
│  · 摩托车: 本田 ADV350                                 │
│  · 当前行程: 摩旅西藏（2026-10）                       │
│  · 当前关注点: Agent 框架选型                          │
│  提取策略: 每次对话后检查，有新状态就 upsert            │
├─ Layer 3: preferences（偏好）──────────────────────────┤
│  做事的方式和倾向                                       │
│  · 报告格式: HTML 单文件（不要 PPT）                    │
│  · 沟通风格: 直接给结论，少铺垫                         │
│  · 时间粒度: 日程以天为单位即可，不要拆到小时           │
│  提取策略: 当用户明确表达"我喜欢/不要/应该"时写入       │
└────────────────────────────────────────────────────────┘
```

#### 例子：本田 ADV350 + 摩旅西藏 怎么被沉淀

```
用户: "我开的是本田 ADV350，准备下个月去摩旅西藏"
 │
 ▼
MemoryEngine.tick() 触发（每轮对话结束后自动）
 │
 ▼
llmExtract 分析 → 判断两条新记忆:
 │
 ├─ { layer: 'state', category: 'motorcycle',
 │    content: '驾驶本田 ADV350', confidence: 0.95 }
 ├─ { layer: 'state', category: 'current_trip',
 │    content: '计划 2026-11 摩旅西藏', confidence: 0.9 }
 │
 ▼
upsert 写入 memory_items 表
 │
 ├─ 查 Layer 2 + category='motorcycle' → 无旧条目 → 新增
 └─ 查 Layer 2 + category='current_trip' → 无旧条目 → 新增
 │
 ▼
下次用户问 "帮我规划一个长途旅行的装备清单"
 │
 ├─ Agent build system prompt → 注入 Layer 2 state
 │   → 包含 "驾驶本田 ADV350" + "摩旅西藏"
 │
 └─ LLM 输出自动考虑：
     · ADV350 是拉力车 → 适合高速 + 烂路 → 装备侧重防冻、防摔、备用油
     · 西藏摩旅 → 高反、温差大 → 氧气瓶、保暖层规划
```

#### superseded 策略（自动淘汰过时记忆）

```
用户: "ADV350 卖了，换了川崎 Ninja 400"
 │
 ▼
llmExtract → { layer: 'state', category: 'motorcycle',
               content: '驾驶川崎 Ninja 400', confidence: 0.95 }
 │
 ▼
upsert 时发现同 category 已有条目 (ADV350)
 │
 ├─ 内容冲突 → 旧条目 superseded_by = 新条目 id
 └─ 新条目 status = active
 │
 ▼
下次记忆读取只返回 superseded_by IS NULL 的条目
 → Agent 只会知道 Ninja 400，不会再提 ADV350
```

#### 记忆 vs 知识库的边界

| | 记忆（Memory） | 知识库（Knowledge Base） |
|--|----------------|------------------------|
| **内容** | 用户画像、状态、偏好 | 文章、笔记、图片、文档 |
| **形态** | 结构化 JSON 条目（SQLite 行） | 文件 + SQLite 索引 |
| **来源** | 对话中 LLM 自动提取 / 用户显式说"记住..." | 浏览器插件采集 / Agent 生成 / 用户手动上传 |
| **生命周期** | 旧条目被 superseded，不会累积膨胀 | 持续累积，用户手动管理 |
| **读取时机** | 每次 build system prompt 时**自动注入** | Agent 主动调 `kb_search` 工具时读取 |
| **用户可编辑** | 设置页 → 记忆面板（看/删/改） | 资料库 → 手动管理 |

#### 产品入口（v1）

- **设置页 → 记忆面板**：三层分类展示、每条可看来源会话、手动删除、手动"记住一条"
- **对话中显式触发**：用户说"记住我的摩托车是 ADV350" → Agent 直接调 `memory_write` 工具（跳过自动提取）
- **Agent 内部自动**：每轮对话后 MemoryEngine.tick() 后台执行，用户无感知但记忆已更新

#### 对比总结

| 维度 | WorkBuddy memory.md | Nexa（SQLite 三层记忆） |
|------|---------------------|------------------------|
| 存储 | 单文件 markdown 追加 | 结构化 SQLite 行 + JSON 字段 |
| 分层 | ❌ 无，全部混在一起 | ✅ 三层（profile / state / preferences） |
| 自动提取 | ❌ 无，Agent 每次自己读文件 | ✅ MemoryEngine + LLM 自动提取 |
| superseded 淘汰 | ❌ 旧信息永远堆积 | ✅ superseded_by 软淘汰 |
| 去重 | ❌ 无 | ✅ layer+category 去重 + 相似度检测 |
| 注入方式 | 整文件拼进 prompt（越来越长） | 按 session 上下文筛选后精准注入 |
| 用户可编辑 | 手动改 .md 文件 | 设置页记忆面板 UI 操作 |
| 写入触发 | Agent 把对话里的信息 append | MemoryEngine.tick() + Agent 工具调用 |
| 成本 | 随使用时间 prompt 线性膨胀 | 记忆条目稳定（淘汰旧的），注入体积可控 |

**结论**：Nexa 的方案在结构化、可维护性、长期使用成本、信息精准度上**显著优于** WorkBuddy 的单文件方案。唯一的"代价"是实现复杂度高一些，但用 SQLite + 三层 + superseded 模型换来的是长期可用性——用户用了一年之后，WorkBuddy 的 memory.md 可能已经几千行、Agent 读起来又慢又不准，而 Nexa 的 memory_items 表还是几百条、每条都是最新有效信息。
```

### 5.4 召回工具的 API

```typescript
// Agent 可调用的知识库工具
kb_search(params: {
  query: string;           // 自然语言查询
  type?: 'note' | 'article' | 'image' | 'doc' | 'any';

  timeRange?: { since?: Date; until?: Date };

  id: string;
  type: string;
  title: string;
  summary: string;
  keywords: string[];
  tags: string[];
  filePath: string;        // 本地文件路径
  content?: string;        // includeContent=true 时返回
  createdAt: Date;
  score: number;           // LLM 重排分数
}>
```

## 6. 自进化记忆层

### 6.1 记忆的三层结构

```
┌──────────────────────────────────────────────┐
│  Layer 1: 用户静态画像（初始化 + 对话中补充）    │
│  - 姓名、职业、行业、常用语言                    │
│  - 默认模型偏好、时间偏好、沟通风格              │
├──────────────────────────────────────────────┤
│  Layer 2: 动态状态（每轮对话后更新）             │
│  - 当前关注方向、正在进行的项目                  │
│  - 近期决策倾向、情绪线索                       │
├──────────────────────────────────────────────┤
│  Layer 3: 偏好规则（显式提取 + 隐式学习）        │
│  - "做报告用 PPT，控制在 10 页以内"              │
│  - "旅行规划优先民宿，预算 2k/天"                │
│  - "数据分析输出要 CSV + 图表 HTML"              │
└──────────────────────────────────────────────┘
```

### 6.2 记忆提取时机

每轮对话结束后，后台轻量触发：
1. LLM 对当轮 user message + assistant reply 做"是否包含可沉淀信息"判断
2. 如果有 → 生成 JSON 结构的记忆条目
3. 写入本地 `~/.nexa/memory/*.json`
4. 定期（每 10 轮对话）合并去重

### 6.3 记忆如何影响对话

Agent 构建 system prompt 时：
```
System Prompt = 基础角色提示
              + Layer 1 用户画像（始终包含）
              + Layer 2 动态状态（根据上下文相关性筛选）
              + Layer 3 偏好规则（根据当前任务类型筛选）
              + 当前会话上下文
```
